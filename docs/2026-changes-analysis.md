## 详细改动分析

### 1. TensorFlow → PyTorch 迁移 (PR #1)

**做了什么**：
- 将原项目的 TensorFlow 1.x / Keras 框架迁移到 PyTorch
- 更新 `cchess_alphazero/agent/model.py`：重写神经网络层定义
- 更新 `cchess_alphazero/worker/optimize.py`：重写训练循环
- 更新 `requirements.txt`：替换依赖项

**为什么要做**：
- TensorFlow 1.x 已停止维护，与新版本 Python 不兼容
- PyTorch 生态更活跃，社区支持更好
- PyTorch 的动态图机制更易于调试和扩展

**能力对比**：
| 特性 | 原项目 (TF) | 2026版本 (PyTorch) |
|------|-------------|-------------------|
| 框架版本 | TensorFlow 1.3.0 | PyTorch 1.9+ |
| 动态图 | 不支持 | 支持 |
| 调试难度 | 高 | 低 |
| 社区活跃度 | 低（已过时） | 高 |

### 2. 简化版中国象棋 AI (PR #3, #5)

**做了什么**：
- 创建全新的 `simple_chess_ai/` 模块
- 实现完整的象棋规则引擎 (`game.py`)
- 实现策略价值网络 (`model.py`)
- 实现 MCTS 搜索 (`mcts.py`)

**为什么要做**：

- 需要一个轻量级、自包含的模块用于研究和论文
- 降低使用门槛，让更多人能参与贡献

**能力对比**：
| 特性 | 原项目 | simple_chess_ai |
|------|--------|-----------------|
| 网络规模 | 256通道×7残差块 | 128通道×4残差块 |
| 参数量 | ~100M | ~25M (减少75%) |
| 训练方式 | 分布式多进程 | 单进程一体化 |
| GUI依赖 | 需要图片资源 | 纯代码绘制 |
| 单元测试 | 无 | 34个测试 |

### 3. GRPO 训练模式 (PR #5)

**做了什么**：
- 创建 `simple_chess_ai/grpo.py`
- 实现 Group Relative Policy Optimization 算法
- 添加组采样机制和相对优势计算

**为什么要做**：
- 参考 DeepSeek R1 的训练思路
- GRPO 无需 Critic 网络，减少约 30% 内存开销
- 组内相对优势作为奖励基准，训练更稳定

**技术细节**：
```
GRPO 核心思想：
1. 对同一局面采样多个动作（组采样）
2. 计算组内相对优势作为奖励基准
3. 使用相对奖励优化策略网络
4. 无需额外的价值网络（Critic）
```

---

### 4. GNN 特征提取 (PR #5, #11)

**做了什么**：
- 创建 `simple_chess_ai/gnn_feature.py`
- 使用 GAT（图注意力网络）建模棋子关系
- 创建 `simple_chess_ai/action_encoding.py` 动作编码

**为什么要做**：
- 传统 CNN 只能捕获局部特征
- GNN 能显式建模棋子间的攻击/防守关系
- 提升对复杂局面的理解能力

**技术细节**：
- 棋盘转换为图结构（90个节点）
- 使用注意力机制学习棋子间关系权重
- GNN 特征与 CNN 特征融合

### 5. 推理增强模块 (PR #5)

**做了什么**：
- 创建 `simple_chess_ai/reasoning.py`
- 实现基于规则的态势分析

**为什么要做**：
- 增强模型的可解释性

**功能特性**：

- 走法推荐：给出结构化的决策理由

### 6. FP16 混合精度训练 (PR #5)

**做了什么**：
- 在 `train.py` 中集成 `torch.amp.autocast`
- 添加 `torch.amp.GradScaler` 支持梯度缩放

**为什么要做**：
- 减少 GPU 显存占用约 40%
- 训练速度提升约 30-50%
- 支持在消费级 GPU 上训练更大模型

### 7. MCTS 改进 (PR #7, #8)

**做了什么**：
- 修复 Dirichlet 噪声注入（正确注入 root 节点）
- 添加自我检查过滤（过滤非法走法）
- 添加树复用（Tree Reuse）机制
- 添加局面缓存减少重复推理
- 改进策略 logits 处理

**为什么要做**：
- 原项目 Dirichlet 噪声注入位置不正确
- 树复用可显著减少重复计算
- 局面缓存可加速搜索

**技术改进**：
```python
# Dirichlet 噪声正确注入方式
prior = (1 - weight) * prior + weight * noise

# 树复用
reset_root=False  # 保留上次子树统计
update_with_move(action)  # 手动推进 root
```

### 10. 长捉检测 (PR #12)

**做了什么**：
- 在 `game.py` 中实现 perpetual chase 检测
- 添加循环检测算法
- 更新 README 说明规则

**为什么要做**：
- 中国象棋规则要求长捉判负
- 原项目仅实现了长将检测
- 完善规则可提升 AI 正确性

**规则说明**：
- 长将：循环内一方连续将军 → 该方判负
- 长捉：循环内一方始终威胁吃对方非将棋子 → 捉子方判负
- 三次重复且无长将/长捉 → 判和

## 总结

2026 年的项目重启是一次全面的技术升级：

1. **框架现代化**：从过时的 TensorFlow 1.x 迁移到活跃的 PyTorch
2. **功能轻量化**：创建 simple_chess_ai 模块，降低使用门槛
3. **算法先进化**：引入 GRPO、GNN、CoT 等先进技术
4. **工程规范化**：添加单元测试、数据导出、可复现训练
5. **规则完善化**：修复 Dirichlet 噪声、添加长捉检测

这些改动使得项目更适合：
- 学术研究（论文数据导出、可复现实验）
- 快速原型开发（轻量级架构）
- 教学演示（推理增强、中文文档）
